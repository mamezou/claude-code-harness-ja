# サブエージェント委任

本体は判断・レビュー・統合・先方向け最終版に回り、実働(調査・下書き・チェック)
は委任を既定とする。指摘対応の連続でも既定は変わらない。

## 分担とモデル

- repo-survey(sonnet): リポジトリ調査・横断検索・資料要約
- draft-check(sonnet): 送付前の文面チェック / doc-review(sonnet): 差分レビュー
- 下書き・複数資料の統合分析: 汎用エージェントに model: opus を指定
- model指定は必須(省略するとセッション既定のモデルで動きコストが上がる)
- 即答できる質問、1〜2ファイルの小修正、軽い確認は本体が直接やる
- クラウド操作は本体が実行する。ファイル編集は委任してよい(サブエージェント側
  でもhookは発火する)
- 1つで足りる作業を複数体へ分けない。並列は独立な作業に限る。答え合わせ目的の
  自発追加をしない

## 依頼文

サブエージェントは会話文脈を引き継がない。依頼テンプレで目的 /
成果物 / 読者 / 対象ファイル / 完了条件 / 出力形式を書き、依頼者の発言由来の
制約を転記する。曖昧語を使わない(start-approval.md「曖昧な指示」準拠)。

## レビュー(鵜呑み禁止)

採用前に、採否を左右する根拠箇所を本体が現物確認する。未確認が「未確認」と
明示されているか確かめる。外部送付物はexternal-deliverables.mdのチェックを
本体でも通す。出力はそのまま転送せず、統合して返し、不採用の指摘は理由を添える。

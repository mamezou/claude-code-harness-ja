# 外部送付物のチェック

リポジトリ外に出る成果物(Slack / Notion / メール / 先方PDF / 口頭報告)に内部
リポジトリの表現を持ち込まない。対象は先方向けの全送付物、リポジトリを共有して
いない相手(社内メンバ含む)への送付物、外部ツールに渡す依頼文。

## 禁止項目

- 内部パス(相対・絶対)、内部ファイル名、ローカル拡張子の素出し(`.md`、`.ps1`等)
- コミットハッシュ・ブランチ名・PR番号(相手がGitHubを見られる場合を除く)
- ローカル環境固有の情報、内部hook名・rules名
- 外部AIツールへの言及(Codex、ChatGPT等)。レビューの事実は「内部レビュー反映」
  「クロスレビュー反映」と書く
- CLIの生出力の貼り付け。必要情報を本文へ組み込むか整形し、プロンプト・
  ログタグ・ホスト名を除去する

## 作成の手順

- 資料への言及は、本文に展開する / Notion・共有PDF(`exports/`)に置いて参照する /
  図はPNG・PDFで添付する。CLIコマンドは置換子を `<...>` で明示した再実行可能な形
- 作成前に根拠を「確認済み事実」と「推測・未確認」に区分して内部メモへ残し、
  文面に使うのは確認済み事実のみ
- 返信は「質問文の引用 → 結論 → 理由」の順。型・ひな形・設計5点の事前確定は
  send-draft Skill、送付前チェックは draft-precheck Skill を必ず通す
- 同じ説明目的の送付物を複数系統で作らない(1タスク1成果物)

## 複数区分の金額比較

金額比較は算定前に次を内部メモへ固定する。

| 確認項目 | 記録内容 |
|---|---|
| 比較区分 | 各区分に含める環境とアプリ |
| 費用項目 | 固定費、従量費、外部サービス、作業費の別 |
| リソース | 各区分で新設、継続、廃止、共有のいずれか |
| 算定根拠 | 実績、想定、仮定、未確定の別と参照元 |
| 除外項目 | 除外理由と、差額へ与える影響 |

- 既存リソースを「既存だから除外」としない。専用の継続課金は計上し、共有費は
  配賦ルールの有無を明記する
- 未構築環境を単純な倍額で置かない。構成差と仮定を金額より先に示す
- 固定費と従量費を分け、合計に含む・含まない費用を明示する。安く見える場合は
  削減によるものか環境差かを区別する
- 資料間の前提矛盾が出たら、数値修正を続けず、確定設計 → 実環境 → 過去算定の
  順に照合する。既存の調査記録を先に再利用する

## 例外

リポジトリ内に閉じる文書と、共有先がリポジトリを見られると確認できる場合は対象外。
